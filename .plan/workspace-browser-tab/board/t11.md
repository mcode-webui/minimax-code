## Parent

199 — workspace browser tab model specification

## What to build

A web tab carries a **toolbar**: back, forward, reload, and the URL shown read-only.

The commands are not new. `sendBrowserCommand` is wired end to end — the port member, the
transport's request table (`packages/webui/src/client/platform/transport.ts:245`), the server
handler and the runtime service — and the isolated provider already implements `navigate`,
`reload`, `back`, `forward` and `open_tab`
(`packages/webui/src/runtime/browser/isolated-chromium/provider.ts:429-476`). What is missing is
the only thing: **a client caller**. The browser suite has never driven these commands from the
interface.

There is no persistent address bar. A person who wants another URL presses "+" and types it in the
new tab page.

## Acceptance criteria

- [ ] A web tab shows back, forward and reload, and the URL read-only.
- [ ] Back and forward move through the page's own history, and the generation follows the page
      so a reference recorded before the move is refused.
- [ ] Reload re-reads the page, and the title follows.
- [ ] The commands go through the existing `sendBrowserCommand` path; no parallel command path is
      introduced.
- [ ] A command the surface does not support fails with the stable, explicit error it already has.
- [ ] A person cannot type a URL into a web tab — the only address box is in the new tab page.
