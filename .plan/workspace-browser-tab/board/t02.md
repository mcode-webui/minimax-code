## Parent

199 — workspace browser tab model specification

## What to build

The isolated Chromium provider stops driving one page and starts driving **one page per web
tab**.

Its single page becomes a per-target map: target id → session id and generation. The session is
resolved by target in `sendCommand`, `sendInput`, `startImageStream` and `stopImageStream`, and the
generation check is per target rather than per browser.

The screencast and the frame callback become per target as well. A frame is routed to its page by
the **envelope's** session id — `event.sessionId`, the flattened target session the CDP connection
puts on the event (`cdp-connection.ts:233-240`) — and **not** by `event.params.sessionId`, which is
the numeric screencast acknowledgement id.

The generation accounting is the part that has to move with the map, and it is three sites:

- `provider.ts:251` — `listTargets` reports a constant `1` for every page that is not the launch
  page. It reads the page's own generation instead.
- `provider.ts:229` — `Page.enable` goes only to the launch page's session. Every page needs it, or
  a page that is not the launch page never receives the navigation events that raise its generation.
- `provider.ts:532` — the generation is raised only for the launch page's session. The raise
  becomes per page, keyed by the event's own session.

## Acceptance criteria

- [ ] Two pages of one isolated Chromium can each be driven, streamed and input into independently.
- [ ] A navigation on one page advances that page's generation and leaves the other page's alone.
- [ ] A reference recorded against a page's previous generation is refused on **every** page, not
      only on the one the browser was launched with.
- [ ] A frame is delivered to the page that asked for it and to no other page.
- [ ] The frame's page is resolved from the envelope's session id.
- [ ] The provider's public surface is unchanged for everything that does not involve a second page:
      the same target state shape, the same errors, the same command vocabulary.
- [ ] The provider's own comment about the single page is replaced by the rule that replaces it, and
      the new rule names why the generation is per page.
