## Parent

#176 — WebUI Browser Use specification

## What to build

The last pass: the feature is reviewed against the decision record and attacked, the repository's
own gates pass, the published source projection contains only reviewed files, and the documentation
describes what the code now does.

An attacker's version of this feature is a page that spoofs the WebUI's origin, an extension that
is not the one the person installed, a stale credential, a frame that is too large, a second
connection for a browser that is already paired, an element reference from a page that is gone, an
operation issued after the switch was turned off, and a command the browser does not support that
fails quietly instead of failing honestly.

## Acceptance criteria

- [ ] A security review covers pairing, credential storage, extension admission, the all-tab
      authority the extension grants, input routing, stream limits, cancellation, logging and the
      error paths, against ADR 0019 and the protocol pinned in ticket 01.
- [ ] Adversarial tests cover: origin spoofing, a non-loopback host, the wrong browser identity, an
      old pairing credential, oversized and malformed frames, a duplicate extension connection, a
      stale target generation, an unauthorized operation, the Full CDP command gate in both states,
      and revocation during an in-flight action.
- [ ] There is explicit proof that extension pairing credentials are rejected and accepted correctly
      when the generic service runs in its development mode.
- [ ] There is explicit proof that a command the provider does not support fails as unsupported,
      rather than silently falling back to another command or another surface.
- [ ] The built-client scenario runs through the packaged production entry with installed
      extensions. The development entry is verified too, but it is never accepted as a substitute
      for the packaged-entry acceptance.
- [ ] The new package and file list, the workspace membership, the release inventory and the
      standalone bundle boundaries are reviewed; the source inventory is regenerated and the source
      check passes.
- [ ] The source-owned architecture, runtime and client documents are updated for implemented
      behaviour only, and only after the source and its tests establish it. ADR 0019 remains the only
      Browser Use decision record, and no second decision list is created.
- [ ] Every surface in the acceptance matrix has a recorded result: the isolated Chromium, Edge and
      Chrome. A surface that was not exercised on a platform is called out explicitly rather than
      inferred from another platform's result.
- [ ] Every applicable repository gate passes for the final inputs.
