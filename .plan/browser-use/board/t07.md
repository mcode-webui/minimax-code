## Parent

#176 — WebUI Browser Use specification

## What to build

Element references belong to the page they were found on. When the target changes — the Agent picks
another tab, the tab closes, the browser restarts, the extension reconnects — the old references
must stop working, and they must fail with an error that says so rather than quietly acting on
whatever page happens to be current.

The same target also has to behave predictably under concurrency: two operations against one tab
take turns, while operations against different tabs proceed at the same time.

## Acceptance criteria

- [ ] Every target selection and observation carries a generation, and the generation is visible to
      the client and to the Agent's tool responses.
- [ ] Changing the target, closing the tab, restarting the browser and reconnecting the extension
      each bump the generation of the affected target.
- [ ] An element reference from an earlier generation is rejected with a stable error and is never
      applied to the new page.
- [ ] The rejection is distinguishable from a "no such element" error, so a caller can tell a stale
      reference from a genuinely absent one.
- [ ] Operations against the same tab are serialized; operations against different tabs proceed
      independently.
- [ ] The concurrency behaviour is proven by a test that starts two operations on one tab and two on
      different tabs, and observes the ordering each pair allows.
- [ ] The generation is defined in the shared contract, so the client and the server read the same
      definition.
