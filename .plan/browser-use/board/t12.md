## Parent

#176 — WebUI Browser Use specification

## What to build

The person can drive their own browser from the panel: clicking, typing and text entry reach the
selected tab of the selected browser, and the Agent sees the result in the same tab.

The input is bound to both the target and the browser, so it can never land in another browser's
tab or in a tab the person has moved away from.

## Acceptance criteria

- [ ] Pointer, keyboard and text input from the panel reaches the selected external tab.
- [ ] The input is bound to the target's generation and to the browser identity; input aimed at a
      superseded target is rejected with a stable error.
- [ ] Input to a browser that has been switched off, or whose pairing credential was revoked, fails
      with a stable error and is not silently dropped.
- [ ] The input reaches the same tab the panel is displaying, and the Agent's view of that tab
      reflects it.
- [ ] The extension forwards the input within its own permission model; an input the browser refuses
      is reported as refused rather than as success.
