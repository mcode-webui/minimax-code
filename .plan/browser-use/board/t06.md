## Parent

#176 — WebUI Browser Use specification

## What to build

The Agent's browser tools and the person's panel drive one browser session. An action the Agent
takes is visible in the panel, and an action the person takes is visible to the Agent. Neither side
can be pointing at a different page.

## Acceptance criteria

- [ ] An Agent browser operation and a user action in the panel affect the same page instance.
- [ ] Browser tool availability follows the persisted browser authorization, not provider presence
      and not tool-schema exposure.
- [ ] Tool exposure is bound to the provider's current target and session, so a tool cannot act on a
      target the provider has already left.
- [ ] A tool call against a closed, missing or changed target fails with a stable, explicit error.
- [ ] The browser tools reach the provider through the existing host-supplied provider seam and the
      browser-core transport contract; no parallel browser action path is introduced.
- [ ] The evidence names the seam it exercises: a provider-level test proves the routing, and the
      claim that the panel and the tools share one session is backed by an observation of both acting
      on one page.

## Source

- ADR 0019 — the person and the Agent both operate the selected browser session; the tools and the
