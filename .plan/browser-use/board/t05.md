## Parent

#176 — WebUI Browser Use specification

## What to build

The person clicks and types in the Browser panel, and the page the Agent is using reacts. The
input lands on the same browser session the panel is showing, not on a second copy of the page and
not on a different tab.

## Acceptance criteria

- [ ] Pointer input in the panel reaches the same page instance the panel is displaying.
- [ ] Keyboard and text input reach the same page instance.
- [ ] Input is submitted as a validated command; malformed input is rejected with a stable error
      rather than being forwarded.
- [ ] Input is bound to the target it was aimed at. Input for a target that has since changed or
      closed fails with a stable error instead of landing on the new target.
- [ ] Cancelling the image stream cancels the pending input and releases the provider-side resources
      it held.
- [ ] The input path is covered end to end against a real page, not only against a recorded
      fixture.

## Source

- ADR 0019 — the person using WebUI and the Agent can both operate the selected browser session;
  browser tools and the panel must address the same underlying session.
- Plan — WP4, "forwards pointer, keyboard and text input through validated commands".
- Research notes — #174 browser-core contracts and client conventions (the input surface the
  provider contract offers).

## Verification

- `pnpm typecheck:webui`
- The focused client unit suite, then `pnpm test:webui`
- `pnpm build:webui`, then `pnpm test:webui-browser` for the built client, with a real page
  receiving the input
