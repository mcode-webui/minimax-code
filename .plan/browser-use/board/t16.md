## Parent

#176 — WebUI Browser Use specification

## What to build

A browser that suspends its extension's background worker is a normal event, not a failure. When
the worker comes back, the bridge must re-establish exactly the connection it had — the same
authorized browser and the same target — or say clearly that it could not.

Two cases matter and are different: the worker dies while a frame stream is flowing, and it dies
while a browser command is in flight. The first ends the stream. The second ends the command with an
explicit error, because the command's outcome is unknown.

## Acceptance criteria

- [ ] A service-worker termination during an active image stream ends the stream with a stable
      error, and the selected target is unchanged.
- [ ] A service-worker termination during an in-flight browser operation fails that operation with
      an explicit error, and the operation is not replayed.
- [ ] After the worker restarts, reconnection resumes only the same authorized browser and the same
      target. If it cannot, the specified explicit failure is returned instead.
- [ ] A second extension connection for a browser that is already connected is refused. The
      established session is not silently replaced, and the person is not left with a half-switched
      browser.
- [ ] The reconnection is admitted through the same dedicated path, with the same credential and
      identity checks, as the first connection.
- [ ] The behaviour is observed with a synthetic peer, and separately against a real installed
      extension on a supported browser version.
