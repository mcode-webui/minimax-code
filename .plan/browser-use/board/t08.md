## Parent

#176 — WebUI Browser Use specification

## What to build

A second, independent switch that widens what the Agent may ask a browser to do. With it off, the
Agent uses the restricted command set that ordinary browser use needs. With it on, the Agent may use
every command the active browser and provider actually support, including the diagnostic and
internal capabilities that are not otherwise reachable.

The switch is a grant, not a promise of parity: a browser that does not implement a command still
does not implement it, and the user must be told so rather than being shown a silent fallback.

## Acceptance criteria

- [ ] Full CDP access is a separate switch from the three browser switches, and is off by default.
- [ ] With it off, ordinary browser operations work through the restricted command set, and any
      full-CDP-only command is denied.
- [ ] With it on, every command the active provider actually supports is exposed — no more, and no
      less.
- [ ] The gate is enforced in the runtime and provider path, so a client request cannot bypass it
      by asking for a wider command set directly.
- [ ] A command the provider does not support fails with an explicit unsupported error, naming the
      command, and never falls back to a different command or a different surface.
- [ ] Turning the switch off blocks further full-CDP calls and ends the full-CDP-only streams, while
      ordinary browser operations continue to work.
- [ ] The gate is provider-agnostic: the same rule applies to the isolated Chromium and to the
      extension-backed browsers.
- [ ] The Settings control describes that the switch grants diagnostic and internal browser
      capabilities, so the person knows what they are granting.
