## Parent

199 — workspace browser tab model specification

## What to build

The **new tab page**: the launcher a newly opened tab shows.

It offers four tiles — changes, terminal, canvas and files — and a URL box. Choosing a tile
replaces the current tab's content; typing a URL in the box replaces it with a web page, which is
a request to the runtime to open a page.

The tiles are the add menu's entries today, minus the browser: the browser's kind is deleted, and
a web tab is opened by typing a URL or by the Agent. The changes tile keeps its current
requirements — it needs a session and a working directory.

The URL box is a plain input. Opening a page is the browser business's command, reached through
its port; the launcher does not publish a second browser component to ask.

**The strip's "+" is the opener, and it opens a fresh tab showing the new tab page.** The add menu
is not replaced by a launcher over the same button; it becomes the launcher's tiles, and the
button's meaning changes from "add a tool tab" to "add a tab". A person who wants another URL
presses "+" again and gets a fresh new tab page, because the one they used is now a web page and
has no URL box.

## Acceptance criteria

- [ ] A newly opened tab shows the new tab page, with the four tiles and the URL box.
- [ ] Choosing a tile replaces that tab's content with the tool, and the tab is not closed.
- [ ] Typing a URL in the box opens a page and the same tab becomes the web page.
- [ ] A URL is refused when the isolated browser's switch is off, with the same refusal the Agent
      path uses.
- [ ] The launcher has no address bar outside it: a web tab shows its URL read-only, and a tool tab
      shows none.
- [ ] The "+" opens a fresh tab every time, so a person who wants a second URL gets one without
      losing the first tab.
- [ ] The browser's old add-menu entry is gone, and the browser tool tab is not reachable.
