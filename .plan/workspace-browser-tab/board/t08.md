## Parent

199 — workspace browser tab model specification

## What to build

The workspace's tab shape changes from a discriminated union keyed by kind to a **stable id plus a
mutable content**. A tab that shows the new tab page and the same tab that later shows a web page
are one tab, and the strip does not flicker when the content changes.

The kinds become the content descriptors, and `browser` is deleted from them.

The kind being fixed is load-bearing in more places than the id derivation, and every one of them
has to be re-thought against a mutable content
(`packages/webui/src/client/features/workspace/projection/workspace-panel-state.ts`):

- `:251` — the id is derived from the kind, so the browser kind is one tab per session and
  directory. The id comes from the client instead, so two web tabs in one session are two tabs, and
  the "the same file opens one tab" behaviour moves from the id to a content check.
- `:287-289` — opening a files tab drops every other files tab. That singleton was a consequence
  of the id, not a policy.
- `:279`, `:283` — the workspace review and the turn review get the **same** id, so one overwrites
  the other. They have to be able to coexist.
- `:155-157` — the label is derived from the kind and the review's source. It follows the content.
- `:299-303` — the shape is narrowed on `kind === "review"`. The narrowing follows the content.

And the strip's rendering narrows on `activeTab?.kind` in 28 places in
`packages/webui/src/client/features/workspace/ui/WorkspacePanels.tsx`.

**The stale-read hazard.** The file results and the review summary are cached **by tab id**, while
the effects that read them depend on `[activeTab?.id]`. Today the id changes when the content
does, so the effect re-runs. With a stable id and a mutable content, the effect does **not** re-run
and the component reads the entry the previous content wrote. The cache key or the effect
dependency — or both — have to move to the content.

## Acceptance criteria

- [ ] The tab shape is a stable id plus a content descriptor, and the content carries the kind.
- [ ] One session can hold two web tabs, and they are two tabs.
- [ ] The same file still opens one tab, and the rule is a content check rather than an id
      derivation.
- [ ] The workspace review and the turn review can be open at the same time, and neither overwrites
      the other.
- [ ] A tab's label follows its content, including which review it is.
- [ ] Changing a tab's content re-reads what the tab shows: a tab that changes from "files" to a
      web page does not keep rendering the file result, and a tab that changes from one file to
      another re-reads it.
- [ ] The `browser` kind is gone from the enumeration, and nothing mounts the browser tool tab.
- [ ] Every `activeTab?.kind` guard in the strip reads the content instead, and the strip renders
      both tool tabs and web tabs.
