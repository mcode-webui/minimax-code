## Parent

#176 — WebUI Browser Use specification

## What to build

The panel shows a live picture of the tab the Agent is using in the person's own browser. The
extension captures the page and sends frames across the bridge; the panel renders them.

A live frame channel is the place where a careless implementation hangs or floods, so the limits
are part of the deliverable: a bounded frame size, a bounded rate, a defined policy for a slow
consumer, and a clean end to the stream when the person closes the panel.

## Acceptance criteria

- [ ] Image frames captured from the external browser reach the panel and are rendered for the
      selected target.
- [ ] The frame size limit and the frame rate limit are enforced; an oversized frame is refused with
      a stable error rather than being truncated silently.
- [ ] The back-pressure policy is defined and implemented: a consumer that cannot keep up does not
      cause an unbounded queue to grow. Either frames are dropped under a stated rule, or the stream
      reports a stable failure.
- [ ] Cancelling the stream releases the capture resources on the provider side.
- [ ] The stream ends with an explicit, distinguishable error when the browser, the tab or the
      extension goes away, and the panel's target is not changed by that ending.
- [ ] A frame arriving for a target that has changed is rejected rather than displayed as if it
      belonged to the current target.
- [ ] The image transport is proven with a synthetic peer at the level where the frame limits and
      the back-pressure rule can be observed.
