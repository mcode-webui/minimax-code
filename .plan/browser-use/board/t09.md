## Parent

#176 — WebUI Browser Use specification

## What to build

A browser extension for Edge and Chrome, in its own workspace package, that pairs with the WebUI
over a dedicated authenticated loopback WebSocket path.

The person installs the extension and grants its browser permission; enabling the browser's switch
then pairs it automatically. The WebUI's own page-origin policy stays exactly as narrow as it is:
the extension is admitted on its own path, with its own identity and its own credential, and never
by widening the rules that govern ordinary pages.

## Acceptance criteria

- [ ] The extension source lives in a new first-party workspace package, registered in the
      workspace manifest, in the package scope, and in the dependency licence record, and it is part
      of the published source projection.
- [ ] The extension source is outside the WebUI client bundle, imports no WebUI client module and no
      Node runtime implementation module, and runs as its own browser execution context with its own
      manifest and permission set.
- [ ] The extension has its own typecheck command, and that command is registered in the
      repository's verification list. The existing WebUI typecheck programs do not cover it.
- [ ] A dedicated WebSocket admission path exists for extensions and runs before the generic
      WebSocket handler.
- [ ] That path validates: the loopback host, the exact supported extension identity for the
      connecting build, the per-browser pairing credential, the protocol version, the message size
      limits, and the per-browser switch state.
- [ ] The pairing credential is validated on that path even when the generic service runs in its
      development mode; a development-mode bypass does not bypass extension admission.
- [ ] The existing generic page-origin policy is unchanged and still rejects extension origins; no
      arbitrary `chrome-extension://` origin is admitted.
- [ ] Pairing uses a challenge-response exchange. The credential is never written to logs, and it is
      never the per-start WebUI connection token.
- [ ] The extension identity is distinct per build — the Chrome Web Store build, the Edge Add-ons
      build and the developer unpacked build — and is distinct from any other extension identity
      that exists in this repository.
- [ ] The extension's required browser permissions and host permissions are declared, and the
      developer unpacked-install path is prepared.

## Verification

- The extension package's own typecheck command
- `pnpm typecheck:webui`
- `node scripts/source-inventory.mjs --write` then `pnpm check:source`
- `pnpm check:webui-dependency` and `pnpm check:webui-boundary`
- A test that pairs correctly, and tests that a wrong extension identity, a wrong credential, a
  non-loopback host, a wrong protocol version and a disabled switch are each refused — including in
  development mode
