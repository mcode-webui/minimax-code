## Parent

199 — workspace browser tab model specification

## What to build

The acceptance, and the documentation caught up with it.

**The acceptance.** A real isolated Chromium, the Agent's tool opening a real tab, the strip
gaining it, the picture updating, and the person taking over — recorded, not asserted. The
acceptance record for this feature is
`packages/webui/docs/browser-use/09-acceptance-record.md`, and it is written **from** the records
the suites write.

This closes the gap the acceptance record has carried since the first pass: *"The Agent's browser
tools were not driven against a real browser in this pass."* The record says which run it was
written from, and the run is a real browser.

**The documentation.** The browser-use documents describe the code as it stands, and until now the
tab model's rules were `required` — decided, not implemented. They become `implemented`, each with
the file and the line that carries it:

- `packages/webui/docs/browser-use/05-target-identity.md` — the tab-model table.
- `packages/webui/docs/browser-use/01-capability-matrix.md` — the tab model's rows.
- `packages/webui/docs/browser-use/06-runtime-authorization-trace.md` — the per-target stream.
- `packages/webui/docs/browser-use/07-review-findings.md` — round 11's four findings close.
- `packages/webui/docs/browser-use/09-acceptance-record.md` — the gap is gone.
- `packages/webui/docs/adr/0022-…md` — the decision record is amended if the implementation
  contradicts it.
- `packages/webui/docs/architecture/design.md` and `packages/webui/docs/client/ownership.md` — the
  one-writer rule and the ownership statements.
- `packages/webui/docs/known-gaps.md` and `packages/webui/docs/open-questions.md` — the tab model's
  open question is answered or stays open, honestly.
- `CONTEXT.md` — the vocabulary, if the implementation named anything differently.

The records go to this programme's own completion directory, and the suite that writes them names
that path in `packages/webui/test/browser/acceptance-record.ts`.

## Acceptance criteria

- [ ] A real-browser acceptance record exists for the Agent's path: the browser version, the
      operating system, the settings that were enabled, and what was observed.
- [ ] The acceptance record carries a row for the Agent opening a tab, for the person browsing
      alongside it, and for the generation fence on a page that is not the launch page.
- [ ] The gap — "the Agent's browser tools were not driven against a real browser" — is gone from
      the acceptance record, and nothing replaced it with a weaker claim.
- [ ] Every rule in the browser-use documents' tab-model tables is `implemented` with the file and
      the line that carries it, or it is still `required` because it is still not implemented. No
      rule is described as implemented without the code behind it.
- [ ] Round 11's four findings are closed, each with the evidence that closed it.
- [ ] The known gaps and the open questions name this programme's state honestly.
- [ ] The ADR is amended if the implementation contradicts it, **first**, and the affected tickets
      are re-scoped to match.
- [ ] The completion records are written to this programme's completion directory, not to another
      plan's.
- [ ] The published source inventory is regenerated and the source check passes.

## The acceptance matrix

These are the cases the real-browser run has to cover. They are here rather than in the plan
because a worktree cannot see the plan.

| Case | Surface | What has to be observed |
| --- | --- | --- |
| The Agent opens a tab | isolated | A page exists, the run's selection points at it, and the client's strip shows it **and makes it the active tab** |
| The Agent navigates after opening | isolated | The page is at the requested url and the picture follows |
| The Agent acts on a page it did not open | isolated | The action runs on the run's selection, and a stale reference is still refused |
| A person opens a tab while the Agent works | isolated | The Agent's page and the person's page are different, and each shows its own picture |
| A person opens a tab while the run has no selection | isolated | The run's selection becomes the person's page, so the Agent can act on it |
| A person types into their own tab while the Agent works | isolated | The input reaches the person's page, not the Agent's |
| A person types a url in the launcher | isolated | The tab becomes that page, and the url is shown read-only in the toolbar |
| A person closes a web tab | isolated | The page is released, and the runtime's page set follows the strip |
| Back and forward | isolated | The page moves through its own history, and the generation follows |
| The surface's switch is off | isolated | The Agent's `open_tab` **and** the person's launcher path are both refused with `browser_surface_not_authorized` |
| A run with no selection acts | isolated | Every action except `open_tab` is refused with `browser_target_unknown` |
| A session ends — deleted, archived or transferred away | isolated | Its pages are released and no page is left behind |
| A second web tab in one session | isolated | Both are addressable, and the strip shows both |
| A page navigates | isolated | Its generation advances, and a reference recorded against the old generation is refused — on **every** tab, not only the first |
