## Parent

#176 — WebUI Browser Use specification

## What to build

With the isolated browser switch on, the host-owned runtime starts an isolated Chromium in its own
throwaway profile, opens a page in it, and reports that page as an available target the WebUI can
address. With the switch off, no Chromium process starts at all and the surface reports itself
unavailable.

The provider is created by the runtime, not by client code, and it is supplied the same way by both
service entry points: the development entry and the packaged production entry. A change that only
works in the development entry is not done.

## Acceptance criteria

- [ ] With the isolated browser switch off, no Chromium process starts and the isolated surface
      reports an explicit unavailable state.
- [ ] With the switch on, a Chromium process starts in a dedicated temporary profile that is
      separate from the user's own browser profile, and the target list contains the opened page.
- [ ] The provider is supplied consistently by both composition roots — the development server
      entry and the packaged production entry — and the packaged path is exercised, not only the
      development one.
- [ ] Provider construction grants no authorization on its own: with the switch off, Agent browser
      operations are unavailable on this surface even when a provider exists.
- [ ] Readiness and failure are observable: a provider that fails to start surfaces an explicit
      error, and a provider that is still starting is distinguishable from one that is absent.
- [ ] Shutdown releases the Chromium process, the temporary profile directory, the stream pumps and
      any pending input.
- [ ] Shutdown is idempotent, and a startup that fails part way releases everything it had already
      acquired.
- [ ] The real provider path is exercised by the test. A fake provider alone does not satisfy this
      ticket.
- [ ] The provider uses the existing host-supplied provider adoption seam rather than a new
      parallel one, and the browser tool exposure it produces is bound to the provider's current
      target and session.
