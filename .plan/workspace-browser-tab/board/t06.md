## Parent

199 — workspace browser tab model specification

## What to build

A session's pages are released when the session ends.

There is no per-session lifecycle signal to hang this on. The runtime was searched for
`deleteSession`, `sessionClosed`, `session_close`, `sessionDeleted`, `onSessionClosed` and
`expireSession`; the only one is `deleteSession`, and it is a **binding** with no browser-service
edge (`packages/webui/src/server/operation/binding-mechanism.ts:43`).

A session is also not only removed by deletion. `archiveSession` removes one, and so does a
transfer away (`packages/webui/src/runtime/session-transfer.ts:108`). A release that covers only
deletion leaves a page behind for every archived session, and a page in the isolated Chromium is a
live process with a live target.

The release has to be keyed on **the session's end**, not on one operation, and it has to close
the page, drop the target from the registry, and take the run's selection with it.

## Acceptance criteria

- [ ] A deleted session leaves no page in the isolated Chromium, no target in the registry, and no
      selection in the service.
- [ ] An archived session leaves none either.
- [ ] A session transferred away leaves none.
- [ ] The release is not a special case of one operation: the three paths above reach it, and the
      evidence names all three.
- [ ] A session that is still open keeps its pages, and a page that is still open is not closed
      because another session ended.
- [ ] The frames for a released page stop, and a subscriber does not receive a frame for a page
      that no longer exists.
