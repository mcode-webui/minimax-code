## Parent

199 — workspace browser tab model specification

## What to build

The **run's selection** and the **tab the person is looking at** stay two cells, and the two
writers stay the two parties.

- The Agent's actions follow the **run's selection**.
- The person's pointer, key and text follow the **tab they are looking at**.

Today these are one cell, and the panel's input is bound to it
(`packages/webui/src/client/features/browser/application/browser-commands.ts:282-290`). After the
split, an input that kept following the run's selection would type into a page the person is not
looking at.

There is one bootstrap, and it is a bootstrap rather than a co-write: **a person who opens a web
tab while the run has no selection gives the run that page**, because a run with no selection
cannot act at all. It is decided at the moment the page is opened, from the run's selection at that
moment. It is not a standing rule that the person's tab and the run's selection are the same.

## Acceptance criteria

- [ ] A person typing in their own tab does not type into the Agent's page, and the Agent's next
      action does not land in the person's page.
- [ ] The Agent's actions run on the run's selection, whether or not the person is looking at it.
- [ ] A person who opens a web tab while the run has **no** selection gives the run that page, and
      the Agent's next action runs on it.
- [ ] A person who opens a web tab while the run **has** a selection does not move the run's
      selection.
- [ ] The person's input and the Agent's action on the same page are both delivered, and neither
      silently cancels the other.
- [ ] The two cells are named as two cells in the code and in the documents: the run's selection is
      the runtime's, and the tab the person is looking at is the client's.
- [ ] The one writer per cell holds: the Agent writes the run's selection, the person writes the
      tab they are looking at, and neither writes the other's — the bootstrap above being the one
      documented exception.
