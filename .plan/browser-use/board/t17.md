## Parent

#176 — WebUI Browser Use specification

## What to build

The feature works the same way on Edge and on Chrome, and each browser has a build that its own
store can accept. The two store builds come from one shared extension source, and each is
validated against the exact extension identity that store will issue.

The final proof is a real person, a real installed extension, a real browser — once for Edge and
once for Chrome, independently.

## Acceptance criteria

- [ ] The same behaviours hold on Edge and on Chrome, verified independently against the supported
      browser versions, including the manifest-v3 worker lifecycle.
- [ ] A Chrome Web Store build and an Edge Add-ons build are produced from the shared extension
      source.
- [ ] Each store build's exact extension identity is validated at the bridge, and the identity that
      is accepted is the one that store issues.
- [ ] Developer identities are explicit development configuration and are not accepted by a
      packaged build.
- [ ] The packaged build differs from the developer build in exactly the ways the store requires,
      and the difference is recorded.
- [ ] Real installed-extension acceptance passes separately on Edge and on Chrome. Each run records
      the browser version, the operating system, the enabled settings and the observed result.
- [ ] The synthetic and mock integration evidence is kept separate from the real browser evidence,
      and no claim is carried across from one to the other.
- [ ] Store disclosures are prepared for both stores: the single purpose, the permissions requested,
      the data used and the privacy policy, each accurate about the data flow to the local WebUI.
- [ ] Store submission and publication are not performed by this ticket; they remain a separate
      release action.
