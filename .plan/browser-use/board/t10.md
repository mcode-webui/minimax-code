## Parent

#176 — WebUI Browser Use specification

## What to build

The tabs of the person's own Edge and Chrome become targets the Agent can address and the panel
can show. The person sees which tabs exist, which browser each belongs to, which one the active
Agent run is using, and can pick a different one for that run.

The extension authorizes the tabs it can reach; the Agent picks among them per turn. There is no
per-tab permission prompt, and a tab the browser's own policy blocks is reported as unavailable
rather than silently hidden or silently attempted.

## Acceptance criteria

- [ ] Every tab the enabled extension can reach is listed with its browser, title, URL and
      connection status.
- [ ] The target belonging to the active Agent run is indicated, and is distinguishable from another
      run's target.
- [ ] The person and the Agent can both select a target.
- [ ] Selecting a target updates the panel to that target.
- [ ] One run's selection does not overwrite another run's selection, and two runs in different
      browsers keep their targets independently.
- [ ] Edge and Chrome availability is independent: one browser being absent, unauthorized or
      disconnected does not affect the other, and the absent one reports an explicit unavailable
      state.
- [ ] A tab that the browser's policy or API blocks is reported as unavailable. No per-tab
      authorization prompt is introduced.
- [ ] The tab list updates when tabs open, close or navigate, and a closed target becomes an
      explicit error rather than a silent empty selection.
