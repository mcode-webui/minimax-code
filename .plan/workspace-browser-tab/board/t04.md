## Parent

199 — workspace browser tab model specification

## What to build

The runtime owns the session's web tabs and publishes them.

The browser service keeps, beside the run's selection it already has, the set of web tabs the
session has open, and publishes them as a **snapshot**: each tab's id, its target identity, its
title and its URL, and whether it is the run's selection. A snapshot rather than a delta: the
list is small, and a snapshot is idempotent, so a reconnect reconciles instead of drifting.

The snapshot travels on a **new stream operation**, modelled on `watchBrowserFrames`. Registering
it is more than adding a name:

- `packages/webui/src/shared/capability-manifest.ts:141-149` — the browser family's `ready` list
  names the operations the family is ready for; a stream operation that is not on that list is not
  part of the family.
- `packages/webui/src/shared/operation-names.ts:50-57` — the operation-name constants.
- `packages/webui/src/server/operation/operations.ts` and
  `packages/webui/src/server/operation/handlers/browser.ts` — the registry and the handler.
- `packages/webui/src/runtime/port.ts` and `packages/webui/src/runtime/harness/browser.ts` — the
  port member and its binding.
- `packages/webui/src/client/platform/transport.ts:245-247` — the transport's request table.

The client's own copy of the strip is not the authority for the web tabs; the strip renders what
the runtime publishes.

## Acceptance criteria

- [ ] The runtime publishes the session's web tabs, with each tab's id, target identity, title and
      URL, and which one is the run's selection.
- [ ] A client that reconnects receives the same snapshot, and applying it twice changes nothing —
      the snapshot is idempotent.
- [ ] A tab that is closed disappears from the next snapshot.
- [ ] The new operation is registered in the capability manifest's `browser.ready` list, the
      operation-name constants, the operation registry, the server's handler table, the port and
      its binding, and the transport's request table. Every one of those is named in the evidence.
- [ ] The client renders the web tabs from the published snapshot rather than from a parallel copy
      it keeps itself.
- [ ] The tab id is assigned by the client, and the runtime's target identity is carried as the
      tab's binding — a page that navigates keeps its target id and gains a generation, and the tab
      that holds it is still the same tab.
