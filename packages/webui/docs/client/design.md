# Native Design

The session rail exposes Design as a lavender pill directly below the new-task button, with the
original MiniMax Design black octopus as a flat printed decoration inside the lower-right corner.
The button clips the illustration at its rounded boundary. Both actions stay in the fixed rail
header; session import is the first row under Workspace in the scrolling navigation.

Design is the WebUI's native node-graph workspace. The **Design** action in the fixed left rail header opens `/design` in a new browser tab. The right workspace panel's Design entry renders the same feature. The historical `canvas` tab discriminant remains a navigation compatibility value; it mounts the native Design surface.

## Ownership

Each browser document has one Design application owner, constructed and disposed by `createWebuiApplication`. It owns the selected document, authoritative reads, serialized mutations, error outcomes and document history. Its observation interest ends when the surface detaches; accepted runtime execution continues. Gesture previews, selection, uncommitted form values and the rich prompt's caret belong to the presentation.

The WebUI runtime owns the documents, assets, templates and executions under the configured data directory's `webui/design` directory. Both browser presentations read and mutate that authority through `getDesignState` and `applyDesignAction`; neither launches a Mini App nor reads its storage. Mutations use opaque document revisions. A conflicting mutation is reported and the document reread; the client never retries a possibly different intent automatically.

Undo/redo covers locally accepted edits within one observed document revision sequence. An observed update from a run or another view clears that document's history, with an explanation on the disabled history controls. This conservative boundary prevents a historical full-document restore from discarding any newly accepted fields. Each historical mutation reports its lock-protected `committedRevision`; if the response's fresh document is already newer, that observation resets history rather than attributing the external update to the local edit. History generations fence late mutation and undo/redo receipts after such an update; gesture commits separately merge only their geometry into the latest snapshot.

The runtime's `design.open` event is an explicit agent presentation intent. The application routes it to Design and the shell selects the named session and opens its right panel. Intent IDs deduplicate delivery, and a selection epoch prevents a slow read from reopening the panel after the person navigates elsewhere. Ordinary `design.changed` events invalidate interested reads without selecting sessions or opening panels.

## Graph and execution

Node forms, modes, typed ports, model parameter limits and graph/template rules are extracted from AI Node Canvas 1.22.9. The source license and copyright are preserved in `src/shared/design/LICENSE` and the runtime extraction. Native React cards and SVG connections replace its standalone page runtime. Ordinary controls use the shared WebUI presentation contracts; the spatial graph and immutable rich-prompt reference chips are recorded business exceptions.

The editor supports input, text, image, video, audio, result and group nodes; typed connections; prompt inheritance and asset references; templates; local assets; execution progress and explicit cancellation; and host permission/questionnaire replies. Runtime capability and provider failures remain visible. A template application does not start generation. Provider calls require the host's configured capabilities and may consume the account's quota.

A node execution is a host-bound fact, not a model conversation. The runtime resolves the document id, target node id, node form/mode, upstream references and a relevant-input fingerprint before dispatch, refuses a missing required material or unavailable capability before any model/provider request, and stores the execution id and fingerprint with the task. The model is told which document and node it is producing for and is not trusted to return or choose either id; the host writes a successful result back only to the bound node. Plain text nodes run on the existing Turn/model path with an explicit empty tool selection, so the general Agent's bash, file, canvas and global-mutation tools are absent. A future mode that genuinely needs a tool names a narrow allow list in the same trusted request; Turn assembly and the executor intersect it with the session profile and can only remove capability. The request's capability selection is a closed, validated field of the AgentHost contract.

Settlement is fenced by the bound execution id and the input fingerprint. A newer run on the same node replaces the id, and a changed prompt, parameter, model, mode or upstream product changes the fingerprint, so a late result is discarded instead of overwriting the newer node. Trailing horizontal whitespace at the end of the node's own prompt or prompt-segment text is ignored by the fingerprint only: the stored prompt and the text sent to the model keep it, and interior whitespace, newlines and every other field remain exact. Viewport, geometry and status writes are outside the fingerprint: panning, zooming or moving a card does not invalidate a result already in flight. When an input changes during a run, the runtime stops that run's agent or provider before settling the stale attempt, so its signal is aborted, its node lease is released and a retry is not refused as busy; the late result remains fenced and is never written. Cancellation keeps the previous product and records the attempt as interrupted. A provider call that was dispatched but whose outcome is unknown is reported as unknown and is never automatically retried as a paid operation.

## Interaction

Cards keep their material on the canvas. Selecting a card reveals its operation surface and its eligible tool rail; deselection removes those controls. The operation surface keeps a readable screen size as the graph zooms, uses the original 620-pixel prompt width within the available pane, and remeasures when the browser or workspace divider changes size. Mode, model, shape and count retain separate controls and anchored lists. A node header is empty except during inline renaming.

Drag any non-control part of a card to move the selected cards, and use its resize handle to change dimensions. Shift/Ctrl/Cmd toggles selection; Shift-drag selects an area. Node, multi-selection, connection and background context menus retain their distinct source-derived actions. A three-pixel threshold separates clicks from graph gestures. Output-to-input and reverse input-to-output drags draw a live connection and snap to ports; a compatible card can receive the drop. Dropping an output on empty space offers supported downstream kinds. Dropping an input on empty space creates the corresponding typed input and connects its role. Double-clicking empty space creates and selects an image node. Keyboard safeguards preserve focused editors and managed menus; the canvas supports Delete, Ctrl/Cmd+A/C/X/V, undo, Shift+undo and Ctrl/Cmd+Y. Wheel zoom keeps the pointed world position fixed. Reset fits the graph; the minimap includes the visible world rectangle and centers the clicked world position. Grid and system/light/dark theme controls keep their state across refreshes.

The capability panel separates two questions that the old page answered as one. Local media work — browser upload/crop/grid and local FFmpeg — is reported from this machine's own status. Cloud provider tools come from the account's connected connectors, discovered through the existing Connector gateway under the native-client identity, not from a Mini App installation grant. Discovery keeps its real outcome: ready, partially available with named provider failures, no connected account, expired login, failed discovery, or an account that simply does not offer a tool. Only a successful discovery that omits a tool means "the account does not provide it"; a failed discovery is never rendered as "not granted", and the tool list is never replaced by an empty all-or-nothing inventory.

Templates, assets, capabilities and tools are managed anchored panels. Destructive confirmations alone are modal. Templates keep their original groups, own-template deletion confirmation, inline save-name flow, direct local-file application and local path export. Importing a file does not implicitly add it to the owned template directory. The path panel offers Downloads/Desktop/Documents/Home shortcuts; the runtime writes only existing Design content to the explicitly chosen path, with a separate overwrite choice. The library shows native reference status, sizes and names, supports centered insertion and local export, and delegates deletion and unreferenced cleanup to the runtime.

Image crop operates over the source card with constrained move/resize handles; grid split uses the original geometry plans. Both execute in the browser and publish reusable, arranged result nodes through the runtime. Video/audio trim retains the frame strip or waveform, range handles, playhead keyboard/pointer control and bounded preview loop; closing the panel stops its preview. Card and toolbar tools share the original eligibility and disabled-reason policy. Tool inputs are the node's material followed by unique connected upstream material. FFmpeg tools report missing local dependencies, while model and connector tools use the runtime's execution capabilities. Portable templates retain the original versioned action format. Copied graph references receive new node identities; products remain reusable while execution and session identities are cleared.

Content, view and runtime execution still use the same authority. View changes persist without adding an undo entry. A refused save or typed-node edit retains the attempted document and its actual base revision as a native runtime draft; it does not retry the live mutation. Explicit recovery uses the current document revision and the runtime's three-way merge, preserving newer runtime products and reporting genuine collisions. The original write error remains visible if recovery storage also fails. Drafts use the configured native Design directory, never Mini App storage.

Prompt, category-field and expansion-template editors register their real dirty base and a scoped flush with the existing owner. Board changes, New, template application, conversation navigation, a node run and the document-consuming save/export operations await those flushes before changing scope or dispatching. A refused or unconfirmed flush cancels the command instead of running it on the previous inputs; an in-flight flush is awaited, and all registered editors, including a connected upstream editor, are included. If the live edit cannot be confirmed but its recovery draft is preserved, a run or other document-consuming command is still refused: the draft is kept for recovery, and the authority value is not silently used. Page hiding or leaving sends only those editable fields through the native compact-draft HTTP action, with a genuine base node and draft revision. Requests are coalesced, use keepalive, and must fit the actual 64 KiB UTF-8 body limit. This final lifecycle request is best effort: until a live save or native draft receipt confirms persistence, the toolbar shows pending edits and beforeunload asks the browser to protect the page. Oversized or refused drafts retain that pending state and report a failure; browser termination cannot guarantee delivery. Recovery uses the same native three-way draft merge described above.

Upload, browser-produced media, video poster bytes and bounded lifecycle drafts use the authenticated native HTTP action endpoint, rather than the bounded WebSocket envelope. Other Design actions retain the standard operation wire. Both paths enter the same runtime validator, document locks and persistence owner; HTTP errors preserve their structured code and message. The client reads the HTTP body as text before deciding: a structured JSON refusal keeps its code, while a plain-text 405 is reported as a page/host version mismatch ("restart or upgrade the WebUI host") instead of surfacing a JSON parse error, a plain-text 401 as an authentication failure, and a non-JSON success as an invalid response. The host that does not yet serve the route has to be activated with the new build; the installed Mini App data is untouched.

Each materialized tool response identifies exactly its own new result nodes. The owner lays out those IDs from its latest queued document, preserving content and unrelated concurrent products. Grid tiles retain the original 240-pixel card width and requested column count; other batches use the original square-root column plan. The retained collision rule moves obstructing cards aside, and measured media dimensions trigger a new placement. The created results become selected. The material menu keeps per-file removal and the original append behavior of “换个素材”; cancellation or a failed upload leaves existing references intact.

Runtime questionnaires retain their original step and option identities. Other is exclusive in a single-choice question and can accompany choices in a multiple-choice question. Unselected Other text does not answer a required question. Only explicit user actions answer permission requests. A generated node's conversation action opens its actual runtime session in the shell or a separate authenticated tab.

The persistent task panel shows active tasks and briefly retains settled tasks, provider status, elapsed time and the latest logs. It can be put away and reopens for a new run. Cancel, permission allow/deny, questionnaire submit/skip and conversation fallback execute their real host operations. New conversation is disabled during a run. Ordinary action failures use the shared toast contract; a node's failed-output state and ongoing task state remain on their owning surfaces.

The original page's temporary `output.notice` was written only after a busy-run refusal and was omitted by its output normalizer. Native Design retains the actual running task and node state; an attempted duplicate start reports the runner's refusal through the shared toast. It does not invent a durable notice field. Error content and the original Retry/Cancel/Delete/Report actions share the card's scrollable body with its material, so material cannot cover the error controls. Report copies the original three labeled lines, including the node ID.
